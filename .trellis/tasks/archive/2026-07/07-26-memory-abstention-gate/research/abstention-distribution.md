- 日期：2026-07-27
- 数据：已提交 ablation run `memory-retrieval-20260726T100009Z-700943` 的
  full-baseline 组 + 冻结 embedding cache 离线余弦计算
- 口径：development split，6 个 abstention query / 35 个有相关项返回的 answerable query

## 候选信号逐一验证

### 信号 1：融合语义分绝对下限（原设计主旋钮）——证伪

abstention query 的 top-1 融合语义分：0.5254 / 0.6455 / **1.0000 × 4**。

4 个 1.0 来自基准故意构造的 **HyDE 自证陷阱**：固定假设文本与语料中某条
"近似但错误"的记忆摘要逐字相同（查询问 PR #842，假设编造"PR #824 由 Lin
approve"，语料恰有 #824 的记忆 → 余弦 = 1.0）。绝对下限对它们天然无效。

### 信号 2：原始查询语义分（排除假设通道污染）——证伪

| 组 | top-1 / min 原始余弦 |
|---|---|
| abstention top-1 | 0.452, 0.619, 0.623, 0.740, 0.792, 0.848 |
| answerable 相关项 min（须存活） | 0.371, 0.483, 0.530, 0.587, 0.593, …（p25=0.679） |

两组完全交叠：保护 `personal_reply_language_zh` 的相关项（0.371）要求
floor ≤ 0.37，该 floor 拦不住任何 abstention query。

### 信号 3：假设主导差（hyp_score − raw_score，"自证"检测）——证伪

| 案例 | raw | max_hyp | gap | 真值 |
|---|---:|---:|---:|---|
| parking 陷阱 | 0.619 | 1.000 | +0.381 | 应拒 |
| PR #842 陷阱 | 0.792 | 1.000 | +0.208 | 应拒 |
| allergy 正确答案 | 0.483 | **1.000** | +0.517 | 应收 |
| storage_adr 正确答案 | 0.530 | 0.903 | +0.373 | 应收 |

基准同时构造了"假设与**正确**记忆完全碰撞"的 answerable 案例
（allergy_restaurant），其签名与陷阱不可区分。数据集在设计上就封死了
"用假设主导度判假"的路。

### 信号 4：词法锚点——弱化

PR 陷阱的摘要含 "PR"、"approve" 子串，词法通道同样命中（覆盖 2/3 词项）；
仅缺关键标识符 "842"。二值的"有无词法来源"区分不了陷阱。

## 结论

**#842 ≠ #824 这类判断是实体级语义蕴含问题，任何相似度分数都无法表达。**
基准的陷阱构造（假设碰撞 + 近实体误导）刻意保证了这一点——它逼出的正确
答案是：这类 abstention 必须由能"阅读"记忆原文与问题的机制完成（生成层
或轻量 verifier），检索层分数门只能处理低分尾部。

这与 07-11 参数决策文档"no-answer 更像何时不注入/何时拒答的产品机制问题"
的预判一致，本分析将其从推测升级为数据证明。

## 触发 implement.md ⛔ 审查点

原 PRD 目标（纯检索层规则门，FP 1.0 → ≤0.5，Recall 零损失）在该数据集上
**不可达**。三个候选方向（需用户决策）：

- **A（推荐）：分级 verifier 门**——规则先行（词法锚点/高原始分直接放行），
  仅对可疑候选触发一次 light-model 判定"该记忆是否回答了该问题"；verifier
  拒绝的候选不返回。能过 #842≠#824；成本受分级控制；仍用现有 benchmark
  计量。需修改 PRD（把"轻量生成层判定"从非目标挪入范围）。
- **B：降级目标**——纯规则门只拦低分尾部 + Akashic 式灰区标注，接受
  FP 只降到 5/6~4/6，把"检索层不可分"作为正式负结果写入分析。
- **C：终止实现**——只交付本负结果分析（负结果本身有方法论价值，但不产生
  简历数字）。
