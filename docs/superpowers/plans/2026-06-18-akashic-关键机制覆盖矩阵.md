# Akashic 关键机制覆盖矩阵

> 本文不是新增 Lesson，也不重排已经开始的 40 节课。
>
> 它是 40 节课的覆盖审计表：后续每节课都必须对照这里确认“本课覆盖什么、还没覆盖什么、未覆盖项排到哪一课、对应 eval 是什么”。

## 1. 为什么需要这张矩阵

原 40 节课计划已经给出了合理的大阶段顺序，但粒度偏粗。它能说明“先做 Tool Runtime，再做 Passive Loop，再做 Memory Tools”，但不能保证每个 Akashic 关键机制都被主动发现。

这会导致一个风险：课程把某个模块的外壳做完了，却没有暴露模块背后的关键机制 gap。例如 Lesson 14 讲了 `recall_memory` tool，但如果不主动审计 retrieval quality，就会漏掉 BM25、dense retrieval、RRF、HyDE、sufficiency、rerank、retrieval eval。

因此，从 Lesson 14 起，每节课都必须新增固定检查：

```text
本课覆盖的 Akashic 机制
本课暂不覆盖的 Akashic 机制
暂不覆盖项是否仍属于必须复现
如果必须复现，排到哪一课补
本课对应的 focused test / smoke / eval seed
```

## 4. 40 节课内的补强安排

### Lesson 14-18 必须更细

Lesson 14 不再表述为“完成 memory retrieval 能力”，而是：

- 覆盖：`recall_memory` tool 外壳、tool args -> `MemoryQuery`、structured JSON、evidence/source_ref/citation rule。
- 不覆盖但必须标注：BM25、RRF、HyDE、sufficiency、rerank、retrieval eval。
- 补课位置：Lesson 17-18、Lesson 36、Lesson 39。

Lesson 17 不再只是“query rewrite / sufficiency”，而是升级为：

- Retrieval Quality Pipeline 源码课与 Amadeus 分步复现。
- 至少覆盖：query rewrite、sufficiency、HyDE 的 Akashic 做法、BM25/vector/RRF 的设计位置。
- 如果一次做不完，必须在 Lesson 18 的 gap audit 中保留明确未完成项。

Lesson 18 不只是 memory tool 回归，而是：

- memory tools + retrieval quality 阶段验收。
- 必须输出 retrieval gap audit 和 eval seed。

### Lesson 19-23 必须补 tool discovery

Plugin Mini-Core 不只等于 lifecycle phase。必须显式覆盖：

- tool visibility
- deferred tool / tool_search 思路
- skill catalog 与 plugin registry 的边界
- MCP tools/resources/prompts 与本地 tool runtime 的区别

如果不在 Lesson 19-23 完成实现，也必须在 Lesson 23 gap audit 中明确是否放到 Lesson 40 后扩展。

### Lesson 36-40 不只是“最后补 eval”

Lesson 36-38 先做可观察性：

- trace schema
- prompt/provider/tool/retrieval trace
- inspect API / CLI / TUI

Lesson 39 才做统一 eval harness：

- memory retrieval eval
- tool loop eval
- proactive eval
- drift eval

Lesson 40 做总 gap close：

- 不是“全部做完”的证明，而是明确列出已对齐、未对齐、决定不迁移、下一轮增强。

## 5. 每节课新增强制输出

从下一次 lesson 开始，每份 lesson HTML 必须有一个 `Coverage / Gap Audit` 区块，至少包含：

```text
本课覆盖的 Akashic 机制：
本课明确不覆盖：
不覆盖项是否仍是 Akashic 关键机制：
补到哪一课：
本课 eval seed：
如果我自己重做，第一眼先看哪个 Akashic 文件：
```

如果 lesson 没有这个区块，视为课程设计不合格，不能进入实现。

## 6. 当前 Lesson 14 的修正结论

Lesson 14 仍然成立，但它只能声明自己覆盖 `recall_memory tool boundary`，不能暗示已经覆盖完整 memory retrieval。

必须在 Lesson 14 HTML 和后续 Part 2 中明确：

- 当前 Amadeus retrieval 仍是简化版。
- 现有 `VectorMemoryEngine.query()` 是 vector + keyword max-score，不是 Akashic 级 retrieval pipeline。
- BM25、RRF、HyDE、sufficiency、rerank、retrieval eval 是必须追踪的 gap。
- 这些 gap 不阻塞 recall tool 外壳实现，但必须进入 Lesson 17-18 和 Lesson 39。
