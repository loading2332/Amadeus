对应总计划 Lesson 16 / Part 1 Akashic 源码课

forget_memory / undo：让错误记忆安全失效

本课目标不是马上写 Amadeus 删除逻辑，而是先读懂 Akashic 为什么不物理删除 memory，以及 forget_memory 和 undo 的输入边界为什么不同。

本课目标

  • 理解 forget_memory 是按 memory id 失效记忆，不是删除原始消息。
  • 理解 Akashic 用 status = superseded 做 soft delete，而不是物理删行。
  • 区分 forget_memory 与 undo：一个按记忆 id，一个按消息 source 追踪派生记忆。
  • 为 Amadeus Part 2 设计安全复现边界：先做 soft forget，不做真实 session undo。

与 MISSION.md 的关系

你的目标是把 Amadeus 讲成一个可信的 Akashic 对齐项目。记忆系统如果只能“记住”，不能“纠错”，就不能用于长期 agent。Lesson 16 补的是记忆生命周期里的失效与撤销边界。

测试证明的行为

测试：../akashic-agent/tests/test_forget_memory_tool.py

  • 已有 id 会进入 superseded_ids，数据库行状态变成 superseded。
  • 重复 id 会被去重。
  • 不存在的 id 会进入 missing_ids，不会被静默吞掉。

forget_memory 和 undo 的区别

forget_memory

输入是 memory id。

适合场景：模型已经通过 recall/fetch 确认某条记忆错了，按 id 让它失效。

undo

输入是 message source ids。

适合场景：撤销一轮对话，并处理由这轮消息派生出来的所有 memory。

forget_memory: memory_id -> MemoryMutation(kind="forget") -> status=superseded
undo: message_id -> find source_ref window -> supersede derived memory -> restore replaced old memory

Akashic 的 test_memory_undo.py 说明：如果一条 memory 的 source_ref 是 consolidation window，例如 ["cli:1:0","cli:1:1","cli:1:2"]#h:abc，撤销 cli:1:1 时不能只处理单条消息，必须把这个窗口派生的记忆都纳入回滚判断。

Part 2：Amadeus 复现练手边界

进入实现前，本课建议只复现 Akashic 的安全核心，不做完整 undo。

  • 给 VectorMemoryStore 增加按 id 读取与 status=superseded 标记。
  • 给 memory engine 增加 forget/mutate 风格入口。
  • 新增 ForgetMemoryTool，返回 requested_ids、superseded_ids、missing_ids。
  • 测试 superseded 后 recall_memory 不再返回该 item。

暂不做：删除 session messages、完整 plugin undo、恢复被新记忆替换的旧记忆。这些涉及真实删除和跨模块回滚，必须单独确认。

常见误区

  • 误区：forget 就是删 DB 行。纠正：Akashic 是标记 superseded。
  • 误区：forget_memory 可以拿 message id。纠正：它拿 memory id；undo 才从 message source 追派生记忆。
  • 误区：missing id 可以忽略。纠正：必须返回给调用方，避免模型以为所有目标都成功失效。
  • 误区：实现 forget_memory 时顺手删除 session message。纠正：这是 undo 范围，且需要再次确认。
