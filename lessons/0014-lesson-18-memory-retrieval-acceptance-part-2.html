本课目标与 MISSION.md 的关系

MISSION 要求你能把 Amadeus 讲成有真实架构来源和验证闭环的项目。本课的 tangible win 是：面对一条错误记忆，你能从 prompt block 一直追到 SQLite 状态变化，并解释为什么原始消息不能被一起删除。

  • 说清行为规则、工具执行、检索、解析和存储各自职责。
  • 能从工具返回 JSON 判断下一步应调用 fetch 还是 forget。
  • 能解释联合测试为什么比单个工具测试更重要。

Part 1：Akashic 源码课结论

Akashic 把 recall summary 和 search preview 定义为候选，把 source_ref/evidence 定义为定位合同，把 fetch 返回的原始消息定义为最终证据。Amadeus 复现的是这组接口、数据流和删除边界，而不是照搬目录结构。

候选层：recall_memory / search_messages
定位层：memory ID + source_ref + evidence
证据层：fetch_messages → original messages
纠错层：forget_memory(memory ID) → memory status=superseded

Part 2：Amadeus 完整调用链

BehaviorRulesPromptBlock.render()
  → build_behavior_rules_prompt()
  → LLM 选择 recall_memory
  → Runtime 调 ToolExecutor.execute_async()
  → RecallMemoryTool.execute()
  → VectorMemoryEngine.query(MemoryQuery)
  → tool JSON: memory ID + summary + evidence/source_ref

LLM 选择 fetch_messages
  → FetchMessagesTool.execute()
  → session.fetch_messages()
  → _source_refs_from_evidence()
  → _resolve_source_refs()
  → SessionStore.fetch_by_ids()
  → original messages

若确认旧记忆错误
  → ForgetMemoryTool.execute(ids=[memory_id])
  → VectorMemoryEngine.forget()
  → VectorMemoryStore.mark_superseded_batch()
  → memory status='superseded'

这条链没有传统 Controller/Service/Mapper 命名，但存在等价分层：runtime 是编排层，tool 是接口适配层，engine 是领域服务层，store 是持久化层。

1. 行为协议层：决定“应该怎么做”

amadeus/prompts/__init__.py::build_behavior_rules_prompt() 声明历史检索顺序；BehaviorRulesPromptBlock.render() 把它作为稳定 behavior-rules block 加入 prompt frame。

recall → fetch → factual answer
recall insufficient → search → fetch → factual answer
correction → locate memory ID → fetch → forget memory ID

它负责告诉模型策略，不负责执行查询，也不能保证模型一定遵守。这里最容易犯的错误是把 prompt 文本误认为状态机。

2. Recall 候选层：返回可追溯候选

amadeus/tools/recall_memory.py::RecallMemoryTool.execute() 把工具参数转换成 MemoryQuery，异步等待 MemoryEngine.query()，再把领域对象序列化成 tool JSON。

输出字段职责
idmemory ID，后续纠错的删除目标
summary/score用于筛选候选，不证明事实成立
source_ref/evidence供 fetch 定位原始消息
citation_*声明输出引用合同；当前不负责运行时强制

ToolExecutor.execute_async() 会检测返回值是否 awaitable：async recall 在当前 event loop 中等待，同步 fetch/forget 则直接返回。这延续了 Lesson 17 已确认的异步边界。

3. Fetch 证据层：把定位合同变成原文

amadeus/tools/defaults.py::FetchMessagesTool.execute() 只是工具适配器，真正的解析位于 amadeus/session.py::fetch_messages()：

  1. _source_refs_from_evidence() 从 evidence 提取 source_ref 和 refs。
  2. _resolve_source_refs() 去掉 hash 后缀，解析 JSON message-ID 数组并去重。
  3. SessionStore.fetch_by_ids() 按 message IDs 读取持久化原文。
  4. 若传入 context > 0，改用 fetch_by_ids_with_context() 带回邻近消息。

解析放在 session 层而不是 LLM 或 tool description 中，意味着同一个 source_ref 合同可以被测试和其他调用方确定性复用。

4. Forget 纠错层：失效派生记忆，不删除历史

ForgetMemoryTool.execute() 清洗 memory IDs 后调用 VectorMemoryEngine.forget()。engine 分出 found/missing IDs，store 最终执行：

UPDATE memory_items
SET status = 'superseded', updated_at = ?
WHERE id = ?

这是 soft-delete：后续 active query 只看 active memory，旧记录仍可审计。session messages 位于另一套存储路径，完全不会被这条 SQL 修改。

5. 联合验收怎么读

tests/test_memory_retrieval_acceptance.py 不是检查实现细节，而是检查模块边界能否组合：

  • 把 recall 原样返回的 evidence 直接交给 fetch，必须得到原始消息。
  • 把 search 原样返回的 source_ref 直接交给 fetch，必须得到完整 content。
  • forget memory ID 后，该 memory 被 supersede，但原始 message IDs 仍可 fetch。
  • 工具描述、behavior rules 与 citation/evidence JSON 必须表达同一证据等级。

测试使用真实 SessionManager、SQLite store、VectorMemoryEngine 和生产工具；只用稳定 embedding provider 隔离外部模型 nondeterminism，没有用 fake 替代证据链。

方案权衡

选择收益代价 / 失效条件
工具描述 + behavior prompt改动小，与 Akashic 当前合同对齐模型可能不遵守；强一致时必须上 runtime policy
source_ref 集中解析调用方不重复写 parser格式扩展必须保持 resolver 向后兼容
memory soft-delete保留审计与回滚依据长期需要归档/清理策略
联合测试走生产边界能发现 schema 可组合性问题比纯单测更慢，但当前规模成本很低

验证步骤

  1. 运行 uv run --extra dev pytest tests/test_memory_retrieval_acceptance.py -q，应看到 6 passed。
  2. 在 correction 测试中观察 superseded_ids == [memory_id]。
  3. 观察 message ID 被 forget 时进入 missing_ids。
  4. 再次 fetch 同一 source_ref，确认原始消息数量仍为 2。
  5. 阶段门证据：focused 38 passed、全量 125 passed、ruff 和 mypy 通过。

Akashic Gap Audit 与下一步边界

  • 已对齐：候选/原文分层、evidence/source_ref handoff、memory/message ID 边界、soft-delete、citation 输出合同。
  • 同一机制未完成：Amadeus 没有 citation plugin 式运行时 enforcement。
  • 性能 gap：数据库级独立 candidate retrieval 尚未复现，但当前验收没有 correctness failure。
  • 不能偏离：未来无论加状态机还是 citation hook，都必须复用当前 tool JSON 和 source_ref resolver，不能让第二套临时 parser 出现。
  • 明确不迁移：Akashic 未接生产主链的 QueryRewriter、SufficiencyChecker、HyDEEnhancer。

简历表达：参考 Akashic evidence-first 设计，将长期记忆候选与原始会话证据解耦，通过 source_ref/evidence 建立可追溯回源链，并用跨工具集成测试验证纠错只 soft-delete 派生记忆、不破坏历史消息。
