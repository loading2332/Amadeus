对应总计划 Lesson 11 Part 2

Amadeus Session/History 代码精读与 Gap 收口方案

这节课专门回答：当前 Amadeus 到底已经做到哪一半，还差哪一半。重点不是泛泛讲“session 要更细”，而是用当前 session.py 和 Akashic 的 session/manager.py 对照出真正的收口点。

一句话先说结论

当前 Amadeus 已经做到：tool 中间消息参与当前 loop，assistant 持久化时保存了 tool_chain，session history 不直接保留 raw tool 消息。
当前 Amadeus 还没做到：未来 get_history() 时从 tool_chain 重建 assistant/tool 协议消息序列，再喂回模型。

先看当前 Amadeus 代码主链

run_turn()
-> current turn 内构造 loop_messages
-> assistant(tool_calls)
-> tool(result)
-> final assistant reply
-> session.add_message("user", ...)
-> session.add_message("assistant", reply, tool_chain=...)
-> SessionManager.save()

future turn:
session.get_history()
-> 只返回 user / assistant 纯文本历史
-> 不会从 tool_chain 重建 assistant/tool 协议消息

关键位置： amadeus/runtime.py:101-107、 amadeus/session.py:39-50、 amadeus/session.py:321-342。

逐段精读当前 Amadeus

1. 当前 turn 内

在 runtime._run_tool_loop() 里，tool 消息会进入 loop_messages，这是给当前 loop 用的，不是直接给长期 history 用的。

2. 持久化时

当前 assistant 消息会把 tool_chain 挂进 extra 字段保存下来。也就是说，“执行事实”已经被留住了。

3. future turn 取 history 时

当前 Session.get_history() 只过滤出 user / assistant，并且明确跳过 tool，没有重建 tool 协议消息。

这就是当前的缺口

阶段 当前 Amadeus Akashic
当前 turn 内消息 有 assistant/tool 回灌，能继续 loop 有 assistant/tool 回灌，能继续 loop
持久化形式 assistant extra 保存 tool_chain assistant message 保存 tool_chain，session metadata 也会更新摘要
future turn 取 history 只返回 user / assistant 纯文本，不重建 tool 消息 从 tool_chain 重建 assistant(tool_calls) 和 tool(result)

为什么当前实现只算“做到一半”

  • 你已经有执行事实：tool_chain 没丢。
  • 你也已经避免了长期历史直接堆满 raw tool 噪音。
  • 但模型在下一轮再看历史时，还看不到“过去那轮 assistant 叫了什么 tool、tool 回了什么结果”的结构化因果链。

所以当前状态不是“完全没有 tool history”，也不是“已经和 Akashic 一样”。更准确是：

事实被保存了，但还没有被重建成 future turn 的 model-facing history。

Akashic 是怎么补上这半段的

Akashic 的关键不在 loop，而在 Session.get_history() 的重建逻辑。

  1. assistant message 上保存 tool_chain
  2. 未来取 history 时，遍历 tool_chain
  3. 先重建 assistant 的 tool_calls 消息
  4. 再为每个 call 重建 tool result 消息
  5. 最后再追加最终 assistant reply

对应关键位置： ../akashic-agent/session/manager.py:246-287、 ../akashic-agent/agent/lifecycle/phases/after_reasoning.py:147-172。

Amadeus 的收口方案应该是什么

如果按 Akashic 对齐，下一步不是“把 raw tool 消息直接持久化进 session.messages”，而是：

  1. 保留当前 assistant extra 中的 tool_chain 方案
  2. 增强 Session.get_history()：遇到 assistant message 上带 tool_chain 时，重建 assistant/tool 协议消息序列
  3. 决定最终 assistant reply 和 rebuilt tool sequence 的拼接顺序
  4. 补 focused tests，证明 future turn 真的能看到这些重建后的历史

也就是说，收口方向是 重建 history，不是 直接长期保存 raw runtime 中间消息。

最容易犯的错

  1. 看到当前 history 里没有 tool 消息，就误以为 tool 执行事实没保存。
  2. 为了补 gap，直接把 raw tool 中间消息也持久化进 session.messages。
  3. 以为“assistant extra 里有 tool_chain”就已经等于未来 LLM 真能看到它。

你现在必须能复述的 3 句

  1. 当前 Amadeus 已经做到哪一半？
  2. 当前 Amadeus 还没做到哪一半？
  3. 正确的收口方向为什么是“从 tool_chain 重建 history”，而不是“直接持久化 raw tool 消息”？
