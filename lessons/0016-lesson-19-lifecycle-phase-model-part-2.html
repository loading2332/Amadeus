本课目标与 MISSION.md 的关系

MISSION 要求我们复现经过判断的 Akashic 设计，而不是照搬目录。本课迁移的是生命周期接口、数据流、时序边界与测试思想，不是完整插件系统。

  • 用类型化 context 明确每个 seam 可以看见和修改什么。
  • 让 Gate 的修改被真实下游消费，而不只证明 handler 被调用。
  • 让 Tap 只能观察持久化后的快照，失败不改变 turn 结果。
  • 保留 abort、slots、plugin loader 的后续扩展空间，不提前扩大合同。

最小纵向切片：一次 turn 怎样经过三个 seam

最关键的判断不是“有三个事件”，而是三个事件都放在了有明确下一消费者的位置：BeforeTurn 的消费者是 RuntimeContext 构造；PromptRender 的消费者是 ContextBuilder；AfterTurn 没有业务消费者，只有 observer。

第一层：EventBus 提供两种执行语义

完整文件：amadeus/events.py。emit 保留已有的串行、可替换事件语义；fanout 为 Tap 新增并发和失败隔离。

async def emit(self, event: E) -> E:
    current = event
    for raw_handler in self._handlers.get(type(event), []):
        handler = cast(EventHandler[E], raw_handler)
        result = handler(current)
        if inspect.isawaitable(result):
            result = await result
        if result is not None:
            current = result
    return current

async def fanout(self, event: object) -> None:
    handlers = list(self._handlers.get(type(event), []))
    if not handlers:
        return
    await asyncio.gather(
        *(self._run_observer(event, handler) for handler in handlers)
    )

async def _run_observer(self, event, handler) -> None:
    try:
        result = handler(event)
        if inspect.isawaitable(result):
            await result
    except Exception:
        logger.exception("observer error for %s", type(event).__name__)
问题emit / Gatefanout / Tap
执行顺序注册顺序，前一个修改供后一个读取观察者彼此独立，不承诺完成顺序
异常传播，阻止错误数据继续进入主链记录日志并隔离，主链事实已经成立
返回值可以返回替换后的 event忽略 observer 返回值

第二层：三个 Context 把权限写进类型

完整文件：amadeus/lifecycle.py。

@dataclass
class BeforeTurnContext:
    session_key: str
    user_message: str
    history: list[Message]
    retrieved_memory: str | None
    active_skills: list[str] = field(default_factory=list)
    runtime_metadata: dict[str, str] = field(default_factory=dict)

@dataclass
class PromptRenderContext:
    session_key: str
    attempt_index: int
    attempt_name: str
    runtime_context: RuntimeContext

@dataclass(frozen=True)
class AfterTurnContext:
    session_key: str
    user_message_id: str
    assistant_message_id: str
    assistant_response: str
    tool_chain: tuple[dict[str, Any], ...]
    context_retry: dict[str, Any]

AfterTurnContext 使用 frozen dataclass，表达顶层对象不可重新赋值。它不是深不可变：内部 dict 仍可改。因此当前合同是“只读意图 + 返回值不被消费”，不是安全沙箱。若未来需要跨信任边界，必须进一步转为不可变值或序列化快照。

第三层：TurnLifecycle 隐藏底层事件类型

class TurnLifecycle:
    def __init__(self, bus: EventBus) -> None:
        self._bus = bus

    def on_before_turn(self, handler) -> None:
        self._bus.on(BeforeTurnContext, handler)

    def on_prompt_render(self, handler) -> None:
        self._bus.on(PromptRenderContext, handler)

    def on_after_turn(self, handler) -> None:
        self._bus.on(AfterTurnContext, handler)

    async def before_turn(self, context: BeforeTurnContext) -> BeforeTurnContext:
        return await self._bus.emit(context)

    async def prompt_render(self, context: PromptRenderContext) -> PromptRenderContext:
        return await self._bus.emit(context)

    async def after_turn(self, context: AfterTurnContext) -> None:
        await self._bus.fanout(context)

Facade 的价值不是减少几行代码，而是把 seam 的名字和执行语义绑定。以后 plugin loader 只需要依赖 on_before_turn() 这类稳定入口，不需要知道 EventBus 如何存 handler。

第四层：Runtime 接线决定 seam 是否真的有用

完整调用点：amadeus/runtime.py。构造时复用同一个 EventBus，因此旧的 TurnCommitted 与新的 Lifecycle 不会形成两个互不相干的事件世界。

lifecycle: TurnLifecycle = field(init=False)

def __post_init__(self) -> None:
    self.lifecycle = TurnLifecycle(self.event_bus)

BeforeTurn 必须位于 memory/history 已准备、RuntimeContext 尚未构造的位置：

before_turn_context = BeforeTurnContext(
    session_key=session_key,
    user_message=user_message,
    history=list(history),
    retrieved_memory=resolved_retrieved_memory,
    active_skills=list(active_skills or []),
    runtime_metadata=dict(runtime_metadata or {}),
)
before_turn_context = await self.lifecycle.before_turn(before_turn_context)

history = before_turn_context.history
resolved_retrieved_memory = before_turn_context.retrieved_memory
resolved_active_skills = before_turn_context.active_skills
resolved_runtime_metadata = before_turn_context.runtime_metadata

输入：Runtime 已取得的 turn 准备数据。处理：handler 串行修改。输出：Runtime 显式读回字段。下一消费者：每次 attempt 的 RuntimeContext 构造。少了最后四行，handler 虽然执行，主链却不会改变，这是 lifecycle 接线最常见的“假完成”。

PromptRender Gate：每次 retry 都必须拿到新对象

for attempt_index, attempt in enumerate(attempts):
    context = RuntimeContext(
        workspace_root=self.workspace_root,
        history=history,
        current_user_message=user_message,
        retrieved_memory=resolved_retrieved_memory,
        active_skills=resolved_active_skills,
        runtime_metadata=resolved_runtime_metadata,
        disabled_sections=set(attempt.disabled_sections),
        history_window=attempt.history_window,
    )
    prompt_render_context = PromptRenderContext(
        session_key=session_key,
        attempt_index=attempt_index,
        attempt_name=attempt.name,
        runtime_context=context,
    )
    prompt_render_context = await self.lifecycle.prompt_render(
        prompt_render_context
    )
    rendered = self.context_builder.render(
        prompt_render_context.runtime_context
    )

不能把 Gate 放到 retry loop 外面。因为第二次尝试可能禁用 runtime metadata 或缩短 history；复用第一次被插件修改的 RuntimeContext，会让 section 重复、缓存脏数据或绕过 trim 计划。

AfterTurn Tap：为何必须在 SQLite 和 commit 之后

self.session_manager.save(session)
await self.event_bus.emit(TurnCommitted(...))

result = PassiveTurnResult(
    user_message_id=str(user_record["id"]),
    assistant_message_id=str(assistant_record["id"]),
    assistant_response=assistant_response,
    ...
)
await self.lifecycle.after_turn(
    AfterTurnContext(
        session_key=session_key,
        user_message_id=result.user_message_id,
        assistant_message_id=result.assistant_message_id,
        assistant_response=result.assistant_response,
        tool_chain=tuple(dict(step) for step in result.tool_chain),
        context_retry=dict(result.context_retry),
    )
)
return result

observer 收到 message ID 时，对应记录已经能从 SQLite 查询。Tap 报错只写日志，随后仍返回已构建的 PassiveTurnResult。这就是“观察事实”而不是“参与决定事实”。

与 Akashic 的差异：Akashic 的 after_turn fanout 位于 outbound dispatch 之前；当前 Amadeus 尚无独立 outbound port，所以本课能证明的是“持久化后、返回前”，不能冒充已经复现 dispatch 边界。

常见误区与排错顺序

  • 注册成功就等于接线成功：必须追 handler 改过的数据由谁读取。
  • BeforeTurn 可以随便改 user_message：本切片仍持久化原始输入；修改该字段没有正式合同，不应依赖。
  • frozen 等于深不可变：内部 list/dict 仍是可变对象。
  • Tap 并发意味着更快且有顺序：它只保证等待所有 observer 完成，不保证 observer 完成顺序。
  • 把 PromptRender 放在 retry 外：会使 trim attempt 之间共享插件副作用。
  • TurnCommitted 就等于 AfterTurn：前者是已有 commit 事件；后者是面向 lifecycle 的类型化只读 seam。

排错顺序：调用点是否到达 → context 是否包含预期输入 → handler 是否注册到同一 bus → 修改是否被下一消费者读取 → Gate 异常还是 Tap 日志 → retry 是否创建了新 context。
