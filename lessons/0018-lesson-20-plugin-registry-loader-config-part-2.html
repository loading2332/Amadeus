Part 1：Akashic 源码课回顾

先按职责找三处：Manager 编排加载生命周期；Registry 保存 import 声明；Manager tests 定义可观察合同。Config、Context、EventBus 与 bootstrap 的完整链接放在对应精读段和 Primary Sources。

为什么这样设计：声明侧只描述“我是谁、监听什么”；宿主侧统一决定“从哪里加载、注入哪些依赖、什么时候启停”。复杂点在于 import 不是纯读取：如果后面失败，必须撤销 import 已经写入的全局状态。

Registry：声明状态与导入所有权打开 registry.py
def register_class(self, cls: type) -> None:
    self._classes.setdefault(cls.__module__, []).append(cls)

def remove_plugin_tree(self, root: str) -> None:
    prefix = f"{root}."
    self._handlers.remove_by_module_prefix(root)
    self._classes = {
        path: classes for path, classes in self._classes.items()
        if path != root and not path.startswith(prefix)
    }

def claim_import_path(self, import_path: str, owner_token: object) -> bool:
    with self._ownership_lock:
        owner = self._import_owners.get(import_path)
        if owner is None:
            self._import_owners[import_path] = owner_token
            return True
        return owner is owner_token

输入：class 的 __module__、import root 与 Manager token。输出/状态：按模块保存全部 class，或原子取得导入所有权；cleanup 可删整棵声明树。下一消费者：Manager 检查 exactly-one class，并且只有 owner Manager 能完成或撤销该事务。Registry 放在独立文件，是因为它保存声明事实，不应依赖磁盘扫描或 App 启停政策。

class PluginConfig:
    def __init__(self, values: dict[str, Any]) -> None:
        self._values = deepcopy(values)

    def get(self, key: str, default: Any = None) -> Any:
        return self._values.get(key, default)

    def as_dict(self) -> dict[str, Any]:
        return deepcopy(self._values)
PluginContext 明确批准依赖打开 context.py
@dataclass
class PluginContext:
    event_bus: EventBus
    tool_registry: ToolRegistry
    plugin_id: str

为什么放这里：Config 负责值语义，Context 负责依赖注入，Manager 只负责读取并组装；插件只消费 Context，不自行寻找全局 Runtime。PluginKVStore 每次 mutation 先重新读文件，能看到另一个实例刚写入的值，但当前仍是无锁整文件写，不能声称并发安全或 crash atomic。

共享 EventBus：顺序必须由执行者保证

priority + stable tie + exact off打开 events.py
def on(self, event_type, handler, *, priority: int = 0) -> None:
    handlers.append(_HandlerRegistration(
        handler=handler, priority=priority, order=self._next_order
    ))
    self._next_order += 1
    handlers.sort(key=lambda item: (-item.priority, item.order))

def off(self, event_type, handler) -> None:
    registrations[:] = [
        item for item in registrations if item.handler is not handler
    ]

输入：类型、可调用对象、priority。状态变化：高 priority 先执行，同 priority 保持注册顺序；off 只按对象 identity 删除。下一消费者：emit()/fanout() 使用同一列表快照。

只在 Registry 给 metadata 排序不够：Manager 是逐插件加载的，晚加载插件即使 priority 更高，也可能已经晚注册。真正执行 handler 的 EventBus 必须拥有全局顺序。

bound = functools.partial(metadata.handler, instance)
ledger.append((context_type, bound))
self._event_bus.on(context_type, bound, priority=metadata.priority)
两类所有权必须分清
装饰器产生的 handler 绑定由 host 创建，因此 host 记 ledger 并精确 off。插件如果在 initialize() 里手动 context.event_bus.on(...)，订阅由插件拥有，必须在自己的 terminate() 中取消；Manager 不能猜哪个订阅属于它。

四个容易漏掉的边界：

  • Registry subtree：相对导入的子模块也可能声明 class/handler，只删 root 会留下幽灵声明。
  • sys.modules subtree：不清除就无法真正 fresh reload。
  • ownership claim：两个 Manager 不能同时导入/清理同一技术身份；只有 owner token 能 release。
  • per-manager lock：load_all() 与 terminate_all() 共用 asyncio.Lock，避免半加载与半终止交错。
清理保证的准确边界
Manager 能恢复 host-owned Registry、装饰器 handler 绑定、sys.modules 与自身 bookkeeping。插件在 initialize() 中手动注册的 EventBus subscription 仍依赖插件自己的 terminate() 成功取消；若 terminate 失败，宿主无法凭空识别这类 plugin-owned 资源。
第二遍深读：为什么错误日志只保留安全 stack location 
def _safe_traceback(error: Exception) -> str:
    frames = traceback.extract_tb(error.__traceback__)
    return " | ".join(
        f"file={frame.filename} line={frame.lineno} function={frame.name}"
        for frame in frames
    )

日志输出异常类型和清洗后的 stack location，不输出异常 message 或源码行，因为插件异常可能带 API key 等秘密。tradeoff 是诊断信息更少，但宿主日志边界更安全；完整实现见 manager.py。

# bootstrap.py（仅省略 docstring 与 state invariant 的防御分支）
async def start(self) -> PluginLoadReport:
    async with self._lifecycle_lock:
        if self._state is AppState.CLOSED:
            raise RuntimeError("PassiveApp is closed; build a new app to restart")
        if self._state is AppState.STARTED:
            return self._plugin_report
        try:
            report = await self.plugin_manager.load_all()
        except BaseException:
            try:
                await self.plugin_manager.terminate_all()
            except BaseException:
                pass
            raise
        self._plugin_report = report
        self._state = AppState.STARTED
        return report

async def aclose(self) -> None:
    async with self._lifecycle_lock:
        if self._state is AppState.CLOSED:
            return
        first_error: BaseException | None = None
        try:
            await self.plugin_manager.terminate_all()
        except BaseException as error:
            first_error = error
        try:
            self.session_manager.store.close()
        except BaseException as error:
            if first_error is None:
                first_error = error
        finally:
            self._state = AppState.CLOSED
        if first_error is not None:
            raise first_error

build_passive_app() 只组合依赖，仍处于 NEW，不会偷偷 import 用户代码；调用者必须显式 start()。CLOSED 不可重启，避免拿已关闭的 DB 与已清理的插件做“僵尸恢复”。重复同一种操作是幂等的：重复 start 返回同一 report，重复 aclose 直接返回。start 与 aclose 互斥串行；两者并发时由锁获取顺序决定结果，并非“两个操作组合起来总是幂等”。关闭阶段优先抛 terminate 的首个错误，但仍尝试关闭 store 并保证状态进入 CLOSED。

cli.py 目前只是临时开发 adapter：build → start → run one turn → aclose。未来 channel bot 可以长期持有同一个 STARTED App，并把 channel/session 身份放入 turn context；无需把插件启动逻辑复制到每个 transport。顶层 App.run() 仍未实现。

async def _run_chat(args: argparse.Namespace) -> None:

        workspace_root=args.workspace_root,
        env_path=args.env,
    )

这条链真实经过 workspace、PluginManager、Lifecycle、ContextBuilder、PromptAssembler、Provider boundary、session persistence 和 cleanup。FakeClient 只隔离网络与 LLM nondeterminism，属于测试边界；生产架构没有 fake provider、临时 parser 或硬编码 prompt marker。本轮没有做真实网络/真实 LLM 手工验证，也不应这样宣称。
